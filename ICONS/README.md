Reusable iconography source of truth for all RIC projects.

Emoji-backed semantics are defined in `packages/icons` and `packages/emoji`.

## Unicode Vector Metadata

`@ric/icons` keeps the raw `iconography` export stable, then layers full Unicode
metadata on top through `@ric/emoji-vectors`.

Available helpers:

- `iconMetadata` — every named icon with Unicode codepoints, description,
  embedding prompt text, and deterministic vector preview metadata.
- `describeIcon(key)` — metadata for a named Ricui icon.
- `describeUnicodeIcon(glyph, meta)` — metadata for any Unicode glyph, even when
  it is not yet in the named catalog.
- `iconVector(key)` — deterministic fallback vector for a named emoji icon.
- `iconSimilarity(a, b)` — static emoji/vector similarity for two named icons.
- `iconVectorItems()` — plottable vector items for icon-map visualization.

The vector metadata prefers the baked semantic table from `@ric/emoji-vectors`
when `packages/emoji-vectors/src/baked.data.js` has been generated by
`scripts/bake.mjs`. If the baked table is empty or a glyph is missing, Ricui
falls back to the deterministic codepoint vector at the active dimensionality.
That keeps icon metadata open-vocabulary: unknown Unicode glyphs still return
stable `U+...` descriptors and vectors.
